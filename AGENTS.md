# Инструкции для ИИ-агентов

Qorgan — open-source сканер безопасности репозиториев с AI-агентом. Монорепозиторий на
pnpm workspace:

- `apps/web` — Angular 22, сигналы, SCSS, без UI-библиотек;
- `apps/api` — NestJS 11, TypeORM, Postgres, BullMQ; API и воркер из одного кода.

Обзор — в [README.md](README.md), полные правила — в [CONTRIBUTING.md](CONTRIBUTING.md).
Ниже — то, на чём чаще всего ошибаются.

## Команды (из корня)

Нужна Node 24 (`.nvmrc`); с другой версией Angular CLI не запускается.

```bash
pnpm install
make dev-deps        # Postgres и Redis в Docker
pnpm dev:api         # API на :3000 (нужен apps/api/.env)
pnpm dev:web         # фронтенд на :4200
pnpm lint && pnpm test && pnpm build
```

Фронтенд проверяйте в браузере в демо-режиме: `http://localhost:4200/?mock=1`, любой логин.
Воркер запускайте в Docker: ему нужны сканеры в `PATH`.

## Работать нужно здесь

Весь код живёт в этом репозитории. `qorganapp/qorgan-app` и `qorganapp/qorgan-app-backend` —
старые отдельные репозитории, из которых собран монорепозиторий; изменения в них не вносятся.

## Правила: `apps/api`

- Изменили сущность — нужна миграция. Генерируйте её на отдельной пустой базе со схемой
  предыдущей версии, перенос данных дописывайте вручную и проверяйте `run` → `revert` → `run`.
  Рабочую базу разработчика для этого не используйте.
- Файлы сущностей — только `*.entity.ts`.
- Доступ проверяется в запросе к базе через владельца (`findOwned`, `findManyOwned`).
  Чужой объект — `404`, не `403`.
- Вход HTTP — DTO с `class-validator` и `ParseUUIDPipe`. `zod` — только для инструментов агента.
- Связи с репозиторием — `onDelete: 'CASCADE'`.
- Всё, что приходит из репозитория или от модели, — недоверенные данные: файлы только через
  `Workspace`, внешние команды только через `runTool` и `git()`, секреты маскируются до
  отправки в модель.
- Клонирование, сканеры и вызовы модели — только в воркере, не в API.
- Тесты — без базы: логику выносите в чистые функции, модель подменяйте `FakeProvider`.

## Правила: `apps/web`

- Standalone-компоненты, `OnPush`, `inject()`, сигналы и `input()`/`output()`/`model()`.
  Никаких NgModule, `@Input`/`@Output`, `*ngIf`/`*ngFor`.
- Все HTTP-запросы — методы `core/api/qorgan-api.ts`, типы — в `core/api/api.types.ts`.
- Репозиторий выбирается только из репозиториев текущего пространства: `RepoContext.scoped()`
  и `selected()`; `repositories()` — это все подключённые репозитории.
- `effect`, который вызывает код, читающий сигналы, — через `untracked`.
- Перед записью ответа API проверяйте, что выбранное пространство или репозиторий не сменились.
- Стили — SCSS и CSS-переменные из `src/styles.scss`; новых зависимостей и UI-библиотек не
  добавлять. Стили одного компонента — до 10 кБ.
- Markdown от агента — только через `MarkdownView`, без `innerHTML`.

## Общее

- Контракт API меняется одним изменением: маршрут в `apps/api`, тип и метод в `apps/web`
  и обработчик в `apps/web/src/app/core/mock/mock-backend.ts`.
- Тексты интерфейса и сообщения API — на английском, комментарии в коде — на русском.
- Новая переменная окружения — в оба `.env.example` (корень и `apps/api`).

## Границы

- Не коммитить и не пушить без просьбы. Репозиторий публичный: никаких секретов, `.env`,
  адресов серверов и пользовательских данных в коммитах и описаниях PR.
- Для проверок поднимайте временные контейнеры на других портах и удаляйте их после себя.
- Не запускать реальные вызовы модели и не обращаться к чужим репозиториям GitHub без просьбы.
- В отчёте о работе указывайте, что проверено и чем, и что проверить не удалось.
